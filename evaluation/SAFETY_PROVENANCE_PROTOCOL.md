# Frozen medication safety and provenance evaluation protocol

This protocol and `med_safety_cases.v1.json` are frozen before the first benchmark execution. The first run is a **synthetic engineering evaluation** of the current, narrow amlodipine rules. Developer-authored reference labels need independent clinician verification. These tests do not establish general medication safety or patient benefit.

## Test A: medication safety

- **Corpus:** 108 distinct synthetic vignettes, 12 in each of nine declared strata: amlodipine allergy, current simvastatin, both warnings, unknown allergy, conflicting allergy, different-drug allergy, stopped simvastatin, lookalike names, and clean negatives. The case file stores free text, intended structured facts, expected warning types, expected `supported` types, and whether an amlodipine treatment claim should be marked conflicting.
- **Fixed proposed option:** One amlodipine treatment claim is supplied to the safety gate for every case. This isolates warning detection from whether an LLM happened to suggest amlodipine. The structured pass supplies the intended facts. The text pass runs the production deterministic `extract_safety_facts` function with empty model hints, then the same verifier and conflict detector. It tests this text-extraction branch, **not** the complete LLM-backed `/analyze` route.
- **Evidence:** All pinned amlodipine label passages are supplied to the verifier after manifest/checksum validation. Source retrieval coverage is not tested here. Both supported-warning rules require the exact corresponding label passage. An unknown/conflicting allergy must produce `allergy_status_unconfirmed` with `unverified` status and must not be interpreted as cleared safety.
- **Primary descriptive metrics:** Warning precision = correctly emitted warning types / all emitted warning types; warning recall = correctly emitted expected warning types / all expected warning types. The types include the unverified unknown-allergy warning. False-support rate = unexpected `supported` label-warning decisions / all case × label-warning-type decisions whose expected result is negative. Unknown-allergy abstention = unknown/conflicting cases that emit the unverified `allergy_status_unconfirmed` finding / all unknown/conflicting cases. Report valid treatment-conflict behavior separately. Count every case and show each stratum; Wilson 95% intervals describe the constructed sample only.
- **No tuning after test inspection:** Keep original results even if cases expose parser or detector defects. Any fixes require a new code version and a separately named rerun. Raw case-level records remain in ignored `evaluation/runs/`; publish aggregate counts, hashes, and failure IDs.

## Test B: provenance integrity

- Use the actual pinned manifest and all 26 source passages (17 guideline and nine label passages). For each valid passage, test one valid cited control and five one-factor corruptions: invented citation ID, changed document version, modified passage, wrong source type, and forged retrieved-passage ID. An invented **claim citation** must count invalid even if an unrelated valid retrieved passage remains trusted; a corrupted retrieved passage must be absent from `trusted_passages` and its citation must count invalid. Separately, change the expected SHA-256 for each publisher snapshot and require `checked_bytes` to reject the file. No LLM or Qdrant is required.
- Valid controls must be trusted and counted valid. Ordinary proposed claims remain `unverified` by design; simply observing `unverified` is **not** a pass. Report accepted valid controls and rejected corruptions by mutation type. This measures source identity and fail-closed behavior, not whether a citation semantically supports a clinical claim.

## Human review gate and publication wording

At least one qualified clinician should review the vignette labels and cited label sections without seeing model output; two independent reviewers and reconciliation are stronger. Until that happens, call the labels **developer-authored** and all numerical results **provisional engineering results**. This test set is generated from the same amlodipine label and rule scope as the implementation, so source-derived lexical overlap and incomplete clinical coverage are expected limitations. A separate clinician-authored or independently sourced holdout is needed for external validity.
